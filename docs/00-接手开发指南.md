# 接手开发指南

> 面向“拿到这份包、要继续把它做下去”的人。读完这一篇 + `01-原理与实现.md`，
> 基本就能改代码、构建、验证了。

## 0. 这是什么

一个 **Minecraft 1.20.4 / Fabric / Iris 附属模组**：让 Iris 同时驻留两条完整渲染管线，
副管线整帧照常渲染但输出只进离屏 FBO，因此主副切换只需交换指针（毫秒级）。
另有「副管线截图」：F2 用副管线渲染一帧再存盘。

当前版本 **0.1**（早期版本）。版本号与开发迭代的对应关系见 [`../CHANGELOG.md`](../CHANGELOG.md)。

## 3. 构建

### 方式 A：Gradle + Loom（有网络时推荐）

```bash
cd source
gradlew build        # 产物在 build/libs/
```

`gradle.properties` 里的版本：`mod_version=0.1`；依赖从 Modrinth / Terraformers Maven 拉取
（Iris、Sodium、Mod Menu 的版本也写在这个文件里）。

### 方式 B：离线手工构建（`build-offline.ps1`）

原始开发机没有网络，且 loom 在受限沙箱里会被 `Path.toRealPath()` 挡住（JDK zipfs 不可用），
所以当时用的是「javac + tiny-remapper」手工链：

1. 用 named（Yarn）类路径编译；
2. 用 tiny-remapper 从 named 重映射到 intermediary；
3. 打包成可放进 mods/ 的 jar。

它依赖 `work/build/` 里的预置材料（**没有随包提供**，需要按 `04-构建与验证.md` 重建）：
`libs-named/`（Yarn 类名 jar）、`libs-tools/`（tiny-remapper/ASM）、`cp-inter/`、`cp-named/`、
`named/iris-named.jar`、`named/sodium-named.jar`、`tools/classes/`。

> 校验器用法：`java -cp "libs-tools/*;tools/classes;libs-named/sponge-mixin-*.jar" tools.VerifyTool <jar> <cp-inter> <iris jar> ...`
> 预期输出末尾是 `结果：全部通过`。**改完注入点一定要重新跑一遍。**

## 4. 开发时最容易踩的坑

1. **注入点用 intermediary 名 + `remap = false`。**
   本工程没有 Mixin 注解处理器（没有 refmap），运行时只认 intermediary 名。
   查名字用 `tools/mapquery.py`，别凭记忆写。
2. **改注入点后必须跑校验器**：它会比对 `@Inject` 处理器的参数描述符与目标方法，
   参数写错会静默失效（`require=0`）或直接崩（`require=1`）。
3. **不要在世界渲染“尾部”读 `shouldOverrideShaders()`**：Iris 在收尾时就把它置回 false。
   要在渲染中途采样（见 `WorldRendererMixin` 挂在 `renderSky` 调用处）。
4. **想清“这个设置会不会被烘焙进区块网格”**：只有材质 ID 表 / 渲染类型表 / 顶点格式 /
   AO 等级 / 分离 AO / 方向性明暗 / 体素化光源方块需要重建，其余改了不动网格（`WorldSettings.MeshState`）。
5. **别轻易 bump `versionCounterForSodiumShaderReload`**：它会让 Iris 把两条管线的地形着色器全删重编。
   地形程序的主副缓存由 `SodiumTerrainProgramsMixin` 负责。
6. **离屏渲染前一定要先 `target.beginWrite(true)`**：原版世界渲染在绑定渲染目标之前会
   `RenderSystem.clear(...)`，清的是“当前绑定”的帧缓冲，不先换绑就会把主画面擦掉（1.2.0 的坑）。
7. **F2 的按键回调发生在本帧世界渲染之后**（见 `08-功能-副管线截图.md`）：任何“借一帧渲染”的功能都要多等一整帧。
8. **后台线程里不许碰 GL、也不许碰 Iris 的全局状态**（见 `12-…`）：
   `StandardMacros.createStandardEnvironmentDefines()` 会做 GL 查询，必须在渲染线程先算好；
   **Iris 的 `ShaderPack` 解析本身也会做 GL 查询**（实测三个真实光影包都抛
   `Rendersystem called from wrong thread`），所以解析只能留在渲染线程 —— 后台预编译
   只把「解包」放出去。
9. **别假设 Iris 的阴影渲染目标一定存在**：它懒创建（`shadow.enabled` 或非 Sodium 程序用到阴影采样器），
   而 Sodium 的地形程序懒编译、里面直接 `requireNonNull(shadowRenderTargets)`。
   自己在 `compilePrewarm` 的路径上要调用 `ensureShadowTargets(...)`（MakeUp 的闪退就是这么来的）。

## 5. 后续可以做什么（TODO 建议）

* **版本适配**：目前注入点绑死 Iris 1.7.1 / 1.7.2 + MC 1.20.4。若要做 1.7.3+/1.21，
  最小改动是：更新 `gradle.properties`、用 `mapquery.py` 复核所有 intermediary 名、重跑校验器。
* **把“预编译”做进加载界面**：现在**只有「解包」在工作线程上**（解析与编译都必须留在渲染线程，
  见 `12-…`；0.2 已删掉“用档位调度它们”的那套代码），着色器编译仍占渲染线程一整段。
  要彻底消灭这次卡顿，需要在 Iris 之外
  重建一套“可暂停的管线构造”（把 `ShaderMap` / `CompositeRenderer` 的编译拆成可恢复的步骤），
  或者用 `GL_KHR_parallel_shader_compile` 把同一批程序的编译并行发出去 —— 都属于大改。
* **显存占用提示**：副管线要多吃一整份渲染目标 + 阴影贴图，可以在自检里估算并提示。
* **副管线截图的材质一致性**：0.1.9 已经会“切材质表 → 等地形重建 → 拍 → 还原”。
  仍差的一步是“完全不可见”：两包材质表不一致时，屏幕上的地形在重建期间也会跟着变
  （单套区块网格的固有限制）。要彻底看不见，得让 Iris/Sodium 支持“每条管线各一套网格”。
* **真机自动化测试**：这份包里的验证都是静态的（编译/重映射/注入点/引用/GLSL 解析）。
  理想情况是加一个可脚本化的客户端启动 + 截图回读流程。
