## 2. 沙箱里必须处理的两件事（都是环境问题，不是模组问题）

### 2.1 `user.home` 不是真实家目录 → Gradle 起不来

现象：

```
Gradle could not start your build.
> Could not initialize native services.
   > Failed to load native library 'native-platform.dll' for Windows 11 amd64.
...
Caused by: java.io.IOException: 系统找不到指定的路径。
    at java.io.File.createNewFile(File.java:1043)
    at net.rubygrapefruit.platform.internal.NativeLibraryLocator.find(...)
```

依据：`java -XshowSettings:properties` 显示 `user.home = C:\`，Gradle 于是想在 `C:\.gradle\native\...`
里建锁文件，而 `createNewFile()` 不会创建父目录。

修法：**显式设置 `GRADLE_USER_HOME`**（`handover\build-gradle.ps1` 已经代劳）。

### 2.2 沙箱拒绝 `Path.toRealPath()` → JDK zipfs 半瘫 → Loom / tiny-remapper 失效

现象：

```
java.nio.file.AccessDeniedException: <某个 jar>
    at sun.nio.fs.WindowsLinkSupport.getRealPath(WindowsLinkSupport.java:258)
    at sun.nio.fs.WindowsPath.toRealPath(WindowsPath.java:933)
    at jdk.nio.zipfs.ZipFileSystemProvider.newFileSystem(ZipFileSystemProvider.java:119)   # 打开 jar 失败
    at jdk.nio.zipfs.ZipFileSystemProvider.lambda$removeFileSystem$0(ZipFileSystemProvider.java:322)  # 关闭 jar 失败
```

实测边界（`work\netcheck\Probe*.java`）：

* `Files.exists / size / newByteChannel / newInputStream`、`Files.delete`（普通文件）、`Path.toAbsolutePath` —— 都正常；
* `Path.toRealPath` —— **任何路径**都被拒；
* `FileSystems.newFileSystem(Path,env)` 能开，`FileSystem.close()` 必失败；`newFileSystem(URI)` 连开都失败。

影响：Loom（读 jar 判断 bundle、remap）与 tiny-remapper 都会失败；这正是 `docs/01` §6 坑位 ③、`docs/04` 里记的老坑。

修法：`tools\sandbox\FixRealPathAgent.java`（+ 已编好的 `fix-realpath-agent.jar`）——
用 ASM 在类加载时把 `sun.nio.fs.WindowsPath#toRealPath` 的方法体换成 `return this.toAbsolutePath()`。
对 zipfs 而言“稳定的绝对路径”就够用，于是 zipfs 恢复。用法见 `tools\sandbox\README-sandbox-agent.md`。

> 注意：`build-local.ps1` 的离线链**不需要**这个代理 —— `tools\RemapTool.java` 本来就是为
> “zipfs 不可用”写的（输入用 `ZipFile`/目录、输出用 `JarOutputStream`），这也是它当初存在的原因。

## 3. 为了让工程真的能编过，改了 4 处（都是真问题）

### ① `gradle.properties`：Iris 的 maven 坐标写错

`iris_version=1.7.1+mc1.20.4` 在 Modrinth 的 maven 里不存在，正确写法是 `<iris 版本>+<mc 版本>`：
`1.7.2+1.20.4`（Modrinth 上 1.20.4 只有 `1.6.13+1.20.4 … 1.7.2+1.20.4`）。
0.1.14 的验收报告就是对着 1.7.2 写的（`docs\verification\iris-1.7.2-0.1.14.txt`），所以锁 1.7.2。

### ② `build.gradle`：Mod Menu 的传递依赖缺仓库

`com.terraformersmc:modmenu:9.2.0` 依赖 `eu.pb4:placeholder-api`，只发布在 Nucleoid 仓库，
已补 `maven { url = 'https://maven.nucleoid.xyz/' }`。

### ③ `build.gradle`：关掉 Mixin 注解处理器

Loom 默认会挂 Mixin AP，它按 **Yarn 命名**去找 `@Accessor("field_27740")` 这类成员，当然找不到：

```
WorldRendererAccessor.java:17: Could not locate @Accessor target field_27740 in target net.minecraft.client.render.WorldRenderer
```

而本工程的 mixin 一律是 **intermediary 名 + `remap = false`、无 refmap**（`docs\01` §6 坑位 ② 的设计），
所以按 `build-offline.ps1` 的 `-proc:none` 语义关掉 AP：

```groovy
loom { mixin { useLegacyMixinAp = false } }
```

### ④ `handover\setup-and-build.ps1` / `tools\run-*-test.ps1`：PowerShell 5.1 的两个坑

* `& $java -version 2>&1 | Select-Object -First 1` 在 `$ErrorActionPreference='Stop'` 下会抛 `NativeCommandError`
  （stderr 被并进管道后变成错误记录）→ 该行前后临时放宽错误策略；
* 一键脚本调用两个回归测试时**没有把 `-Materials` 传下去**，测试脚本就退回开发机的老路径而报
  `missing required path` → 已传参，并让两个测试脚本把默认材料目录优先指向 `<repo>\work\materials\build`。

## 4. 新增的脚本 / 文件

| 路径 | 作用 |
| --- | --- |
| `handover\build-gradle.ps1` | Gradle(+Loom) 一键构建：设好 `JAVA_HOME`/`GRADLE_USER_HOME`，自动挂沙箱代理，输出 `source\build\libs\*.jar` |
| `handover\make-materials.ps1` | 用本机已有的东西拼出 `work\materials\build\`（离线链所需的全部材料），并编好 `tools\classes` |

| `tools\sandbox\` | `FixRealPathAgent.java` + `fix-realpath-agent.jar`（内联 ASM 9.6）+ 说明文档 |
| `source\gradlew` / `gradlew.bat` / `gradle\wrapper\*` | 标准 Gradle Wrapper（8.8），IDEA 直接可用 |

## 5. 材料（`work\materials\build\`）怎么来的

`handover\make-materials.ps1` 全部就地取材，不需要下载：

| 材料 | 来源 |
| --- | --- |
| `libs-named\*.jar`（134 个） | Loom 生成的 `source\build\compile-classpath.txt`（含 **Yarn 命名的 MC**、Fabric API、Mod Menu、guava/gson/joml/fastutil/lwjgl/asm…） |
| `named\iris-named.jar`、`sodium-named.jar`、`modmenu-named.jar` | Loom 缓存 `source\.gradle\loom-cache\remapped_mods\<yarn hash>\...` |
| `cp-named\`、`cp-inter\` | 解包后的 MC（Yarn 命名 / intermediary），各 ~22.6k 个 class |
| `iris172-inter\`、`sodium-inter\` | 解包后的 Iris / Sodium（Modrinth 的分发件本身就是 intermediary 命名） |
| `libs-tools\` | toolchain 里的 tiny-remapper + 缓存里的 ASM 9.6 |
| `jars\mappings.tiny` | Loom 缓存里的 Yarn 1.20.4+build.3 映射 |

> 坑位提示：本沙箱里 **javac 读不了“目录形式”的 classpath**（会报“程序包不存在”），但读 jar 正常；
> 而 VerifyTool / RemapTool 需要目录形式。所以材料里 `libs-named` 是 jar、`cp-inter` 等是解包目录，各司其职。

```powershell
  -Materials .\work\materials\build -Mappings .\work\materials\build\mappings.tiny -Version 0.1.14 -Tests
```
