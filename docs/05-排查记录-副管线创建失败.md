# 排查记录：副管线创建失败（1.0.0 → 1.1.0）

> 说明：本文标题与正文里的 `1.x` 是**开发期间的临时迭代号**，对外版本号为 **0.1**（见 [`../CHANGELOG.md`](../CHANGELOG.md)）。

## 现象

`1.20.4-pure` 实例（Iris 1.7.2 + Sodium 0.5.8 + Fabric Loader 0.19.5）里：

* 主管线是 `MakeUp-UltraFast-9.1e.zip`，正常；
* 副包选的是 `BSL_v8.2.07.1`，`[ShaderFlash] 创建副管线失败` 每 10 秒刷一次（重试退避）。

```
[ShaderFlash] 创建副管线失败
net.irisshaders.iris.gl.shader.ShaderCompileException:
    deferred.fsh: deferred.fsh: ERROR: 0:58: 'sample' : syntax error syntax error
    at net.irisshaders.iris.gl.shader.GlShader.createShader(GlShader.java:46)
    at net.irisshaders.iris.pipeline.CompositeRenderer.createProgram(CompositeRenderer.java:326)
    at net.irisshaders.iris.pipeline.CompositeRenderer.<init>(CompositeRenderer.java:123)
    at net.irisshaders.iris.pipeline.IrisRenderingPipeline.<init>(IrisRenderingPipeline.java:315)
    at dev.shaderflash.DuoManager.ensureSecondary(DuoManager.java:223)
```

## 排查步骤

1. **确认不是加载流程的锅。** 日志里能看到副包被正常解析（`Profile: HIGH (+0 options changed by user)`），
   报错发生在之后的着色器编译阶段，说明 `ShaderPack` / `ProgramSet` 都没问题。
2. **定位到是哪一行代码。** `deferred.fsh` 的 include 链是
   `world0/deferred.fsh → program/deferred.glsl → lib/lighting/ambientOcclusion.glsl`，
   而全包里只有三处用到 `sample` 这个词，其中 `ambientOcclusion.glsl:37` 是
   `float sample = (depth - sampleDepth) * mult / currentStep;`。
   报错里的行号 58 是 **Iris 转译并去掉注释之后**的行号，所以和源文件行号对不上。
3. **确认不是本模组的加载方式有问题。** 主管线 MakeUp 同样是 `#version 120` 的老包，
   走的是同一套转译流程，编译正常 —— 两包唯一的差别就是 BSL 那份源码里用了 `sample` 当变量名。
4. **用 Iris 自带的解析器验证关键字规则。** 直接调用 Iris 内嵌的 glsl-transformer
   （`io.github.douira.glsl_transformer`）解析同一段声明：

   | 版本 | `float sample = ...` |
   | --- | --- |
   | GLSL 1.20 | 解析通过 |
   | GLSL 3.30 | 解析通过 |
   | GLSL 4.10 | **语法错误** |

   证据原文：[`verification/glsl-keyword-check.txt`](verification/glsl-keyword-check.txt)。
5. **确认 Iris 1.7.1+ 会转译到 4.10。** Iris 的 `TransformPatcher` 对老包走“兼容转译”分支，
   其中会把版本号提到 `Version.GLSL41` 并把 profile 设成 `CORE`：

   ```java
   // net.irisshaders.iris.pipeline.transform.TransformPatcher
   } else {
       // patch the version number to at least 330
       if (version.number < 410) {
           versionStatement.version = Version.GLSL41;
       }
       versionStatement.profile = Profile.CORE;
   ```

   历史日志也印证了这一点：同一台机器、同一个 BSL zip，在 **Iris 1.7.0** 时代（2024-06 的日志）
   编译与运行都正常；换成 1.7.1/1.7.2 之后 `sample` 就成了关键字。

## 结论

**根因不在双管线机制，而在副包源码**：那份 BSL 里 `sample` 被当作变量名使用，
而 Iris 1.7.1+ 会把所有光影包转成 `#version 410 core`，`sample` 在 GLSL 4.x 中是保留关键字。
主管线换成 BSL 同样会失败（可以在 Iris 的光影界面里切过去复现）。

## 修复（1.1.0）

加载副包前，先把它铺成一份自己的副本，在副本上做一次**保留字改名**：

* 只处理“在 GLSL 1.20 里合法、在 GLSL 4.x 里是关键字”的词：
  `sample`、`subroutine`、`resource`、`partition`、`common`、`active`、`row_major`、`namespace`、`using`；
* 声明处与使用处一起改名（`sample` → `shaderflash_sample`），语义不变；
* 跳过 `#include` / `#pragma` / `#extension` / `#version` / 注释行，避免动到文件路径；
* **只改副本**（`config/shaderflash/packcache/<包名>/`），玩家 shaderpacks 目录里的原文件一个字节都不动；
* 缓存戳记里带上来源大小、修改时间与开关状态，包更新过或改了开关会自动重建；
* 设置界面新增开关“兼容 GLSL 4.x 保留字”（默认开），可随时关掉。

对 BSL 实测：改写 9 处（`ambientOcclusion.glsl` 5 处、`roughReflections.glsl` 4 处），
`sampleDepth` 这类包含关键字的更长的标识符不受影响；
改写后用同一套 GLSL 4.10 解析器复检，`float shaderflash_sample` 通过、裸 `sample` 已不存在。
证据原文：[`verification/reserved-keyword-fix.txt`](verification/reserved-keyword-fix.txt)。

## 顺带修掉的问题

* **选项文件读错名字**：Iris 用的是完整包名（`BSL_v8.2.07.1.zip.txt`），原实现按去掉 `.zip`
  的名字去找，导致副包会丢掉玩家改过的光影设置。现在两种名字都会找。
* **误用主管线的选项队列**：原来把 `Iris.getShaderPackOptionQueue()`（属于主管线、刚改动未保存的值）
  也塞进副包选项里，属于张冠李戴，已移除。
* **报错更直白**：编译失败时会在聊天框给出一句人话提示（保留字 / 版本 / 显存 / 计算着色器四类）。

## 后记（0.1.9）：这个修复被删掉了，理由如下

玩家的反驳是成立的，这里照办并记录理由：

1. **默认加载不了的光影包，玩家不会去用。** 一个包如果在 Iris 里根本编译不过（Iris 也可以
   在光影选择界面里直接加载它，失败时同样失败），玩家就不会选它当主光影，更不会把它当副光影。
   兼容性只服务“本来就会用的包”。
2. **改名修不回已经丢失的语义。** 老代码里那些写法能跑，靠的是旧版 GLSL 的语义；
   把标识符换个名字只是让它“看起来编译得过”，行为并不等价 —— 相当于把编译器报错静音，
   而不是修好代码。真到运行期出错，反而更难排查。
3. **代价与收益不成比例。** 为了这条救不回来的路径，要长期维护一份包改写器、
   一个界面开关、一套缓存戳记与三个离线验证工具。

所以 0.1.9 把 `ReservedKeywords.java`、`fixLegacyKeywords` 配置与界面开关、
`PackPreparer` 的改写分支、缓存戳记里的 `fix=` / `rewritten=`、`PackSlot.rewrittenKeywords`、
相关语言键，以及只服务于该功能的离线工具（`KwTest` / `RewriteTest` / `LegacyAttrRewriteTest`）
全部删除，缓存格式升到 `v4`（旧缓存自动重建）。上文的排查过程仍然保留，
因为它解释了“为什么主管线也失败”，这条结论依然有效。
