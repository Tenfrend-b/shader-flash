# 排查记录：副管线是否生效 & 无感切换（1.2.0 → 1.3.0）

> 说明：本文标题与正文里的 `1.x` 是**开发期间的临时迭代号**，对外版本号为 **0.1**（见 [`../CHANGELOG.md`](../CHANGELOG.md)）。

## 一、“副管线光影不生效”

### 1. 先把自检本身修对

1.2.0 的自检是在**按键回调**（客户端 tick，渲染之外）里读的状态，而
`shouldOverrideShaders()` = `isRenderingWorld && isMainBound` 里的 `isRenderingWorld`
只在 `beginLevelRendering()`…`finalizeLevelRendering()` 之间为真。所以那行 `false` 是必然的，
**什么也证明不了**。1.3.0 改为在世界渲染**中途**采样（注入 `WorldRenderer.renderSky` 的调用处：
此时已过 `beginLevelRendering()`、尚未收尾），并逐个列出程序类名：

```
渲染时的真实状态：IrisRenderingPipeline；shouldOverrideShaders=true，
  TERRAIN_SOLID=FallbackShader，ENTITIES_SOLID=FallbackShader，
  SKY_BASIC=ExtendedShader，CLOUDS=ExtendedShader（Iris 全局阴影标志 ACTIVE=false）
副包自带程序：地形=无 实体=无 水面=无 阴影=无
```

`ExtendedShader` = 该包自己写的程序；`FallbackShader` = 包没提供、由 Iris 合成的近似原版程序。

### 2. 日志里的直接证据：切过去以后 C 的着色器确实在用

每次切到 `CyanideShaders_v1.1` 之后，日志都会紧接着出现：

```
Shader clouds could not find uniform named ModelViewMat in the specified shader program.
Shader clouds could not find uniform named ProjMat / ColorModulator / FogStart / FogEnd / FogColor ...
```

这几条的原意是：**原版**的云渲染器想按原版 uniform 名去设置参数，却发现当前程序里没有这些名字。
会出现这种“找不到”的唯一原因是——云用的是**光影包自己的 `gbuffers_clouds` 程序**（Iris 的着色器覆盖
正在生效）。如果覆盖没生效，用的就是原版程序，这些名字一定找得到、也就不会有警告。

也就是说：**切换后 C 的着色器已经在工作**，它自己的云、天空、色调映射都在跑。

### 3. 那为什么画面像“没开光影”

因为 `CyanideShaders_v1.1` 本身**就不是一个完整的光影包**，而是 XorDev 的
“Default Shaderpack”模板（它自己的 `block.properties` 开头写着：*"This was put together by
@XorDev to make it easier for anyone to make their own shaderpacks in Minecraft"*）。
整包只有这些文件：

```
final.fsh / final.vsh                    ← 色调映射 + 雾 + 泛光
gbuffers_clouds.fsh / .vsh               ← 云
gbuffers_skytextured.fsh / .vsh          ← 天空贴图
gbuffers_textured.fsh / .vsh             ← 带贴图的几何
block.properties                         ← 只有 12 行，基本沿用默认
```

**没有 `gbuffers_terrain`、没有 `gbuffers_entities`、没有水面、没有阴影、没有 composite/deferred。**
所以它当主光影时，地形与实体会走 Iris 合成的 fallback（≈ 原版光照），
画面自然就是“裸方块模型 + 原版亮度 + 一层色调映射”——这是这个包的**设计如此**。

想自我验证很简单：用 Iris 自带的光影界面把同一个 C 加载为主光影，画面会与切换过来时一致。

## 二、“切换时明显的区块卸载/重载”

### 原因

1.2.0 为了修“材质表不重建”，在主副互换时调了 `WorldRenderer.reload()`
（Iris 自己的 `allChanged()` 路径）。这东西会**一次性丢掉所有区块网格**再重建，
玩家看到的就是地形整片消失、再慢慢长回来。

但“要不要重建”其实可以判断得比 Iris 更准。Iris 的 `WorldRenderingSettings.reloadRequired`
是个粗开关，只要它管的任意一项变了就置位；而真正会被**烘焙进区块网格**的只有这几项：

| 设置 | 是否进网格 |
| --- | --- |
| 方块材质 ID 表（`blockStateIds`） | 是（顶点里存材质 ID） |
| 方块渲染类型表（`blockTypeIds`） | 是（决定方块进哪个 RenderType） |
| 扩展顶点格式 | 是（顶点布局本身变了） |
| 环境光遮蔽等级 / 分离 AO | 是（AO 烘焙进顶点） |
| 方向性明暗、体素化光源方块 | 是（Sodium 光照管线在建网格时使用） |
| 实体分离绘制、实体/物品 ID 表 | **否**（渲染时才读） |

### 1.3.0 的做法

1. **精确比较**：只比较上表里“会进网格”的那几项，差异项写进日志与聊天提示。
   两包完全一致 → 切换**零重建**。
2. **逐区块后台重建**（默认开启）：需要重建时不再整体 `reload()`，而是走 Sodium 的
   `SodiumWorldRenderer.scheduleRebuildForChunks(...)`，把视距内的区块段**排队**重建。
   旧网格会一直渲染到对应新网格建好为止 —— 没有任何可见的卸载/重载。
3. **不再丢掉地形着色器缓存**：以前切换时会 bump `versionCounterForSodiumShaderReload`，
   那会让 Iris 调 `IrisChunkProgramOverrides.deleteShaders()` 把两条管线的地形程序全删掉重编
   （几百毫秒的卡顿）。现在完全由本模组的 mixin 按管线切换缓存，两条管线的地形程序常驻显存，
   切换只剩指针交换（日志里的切换耗时 1~6 ms 就是这么来的）。
4. **顶点格式变化**（两个 Iris 包之间不会发生）仍走一次硬重建，因为旧网格的顶点布局已经对不上。

设置界面新增两个开关：

| 开关 | 默认 | 含义 |
| --- | --- | --- |
| 切换时重做区块网格 | 开 | 关掉则永远不重建（切换最快，但若两包分类不同会沿用旧包的分类） |
| 逐区块后台重建（无感） | 开 | 关掉则退回一次性的整体重建（会有可见的卸载过程） |

## 三、顺带修掉的两处

* `Iris.currentPackName` 之前在互换后写的是去掉 `.zip` 的名字，已改为真实条目名
  （`iris.properties` 在 1.2.0 已改）。
* `SodiumTerrainProgramsMixin` 在“目标管线还没有缓存”时会清掉程序并让 Iris 按**当前管线**
  重建；少了这一步，切换后可能继续用上一条管线的地形程序（这是我 1.2.0 遗留的隐患）。
