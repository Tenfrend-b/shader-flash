# 文本与本地化：所有玩家可见文本都在一个文件里

**0.3 起，模组的全部玩家可见文本集中在**：

```
src/main/java/dev/shaderflash/ModTexts.java
```

改文本只需要改这一个文件，改完重新编译即可。

## 为什么放 Java 而不是 lang JSON

原来文本散在 `assets/shaderflash/lang/{zh_cn,en_us}.json` 里，代码用字符串键去取：

```java
Text.translatable("shaderflash.message.swapped", name, millis, saved)   // 键写错了运行期才知道
```

现在每条文本是一个**编译期常量**，代码直接引用它：

```java
ModTexts.text(ModTexts.MESSAGE_SWAPPED, name, millis, saved)
```

好处：

* **改名/删除会直接编译不过** —— 不会再出现“翻译键打错、游戏里显示成一串键名”；
* 一处定义、一处修改，界面/聊天/HUD/自检不会各写一份；
* 中英两版并排放在同一行，润色时不会漏掉另一半。

## 怎么改

```java
public static final LText MESSAGE_SWAPPED = new LText(
	"已切换到 %s，耗时 %s ms（重新编译这条管线本来要 %s）",   // 中文
	"Switched to %s in %s ms (a fresh compile would have cost %s)");  // 英文
```

* `%s` 是占位符，按出现顺序替换；`%%` 表示一个字面百分号；
* 英文留空字符串时，会退回显示中文；
* 占位符个数写错**不会崩游戏**：日志里会出现一条 WARN，界面上按原文显示；
* 语言选择：游戏语言以 `zh` 开头（`zh_cn` / `zh_tw`）用中文，否则用英文。

## 目前覆盖了什么

| 分组（文件里的分节） | 出现位置 |
| --- | --- |
| `SCREEN_*` | 设置界面标题、选包页 |
| `SECTION_*` | 设置界面的分节标题 |
| `OPTION_*` / `NOTE_*` / `BUTTON_*` / `VALUE_*` | 设置界面的开关、说明、按钮、取值文案 |
| `STATUS_*` / `TAG` | HUD 与设置界面顶部的状态块 |
| `MESSAGE_*` / `HINT_*` | 聊天框提示 |
| `DIAG_*` / `LABEL_*` / `HEALTH_*` | 「兼容性自检」的输出 |
| `HUD_CAPTURE_*` | 截图进度块 |
| `POLICY_*` | 「截图副管线性能调度」五档名称 |
| `PREWARM_PHASE_*` | 预编译阶段名 |
| `ERROR_*` | 状态行里的失败原因 |

## 两个例外（有意保留）

1. **按键文本**（`key.shaderflash.swap` / `toggle` / `screen` / `key.categories.shaderflash`）仍在
   `assets/shaderflash/lang/*.json` 里：Minecraft 的按键系统按**翻译键**解析它们，
   Java 常量喂不进去。两份 JSON 现在只剩这 4 条 + 一条说明。
2. **日志文本**（`[ShaderFlash] …`，只出现在 `latest.log`）没有搬进来：那是给排查问题用的
   技术描述（含类名、数字、阶段耗时）。如果也要一起润色，说一声即可搬到
   `ModTexts` 的 `LOG_*` 分组。

## 编译

```powershell
powershell -ExecutionPolicy Bypass -File handover\setup-and-build.ps1 `
  -Materials .\work\materials\build -Mappings .\work\materials\build\mappings.tiny -Version 0.3 -Tests
```

`-Version` 决定 jar 文件名与 `fabric.mod.json` 里的版本号；`gradle.properties` 里的
`mod_version` 也要同步改成同一个值（Gradle 链用它）。

版本约定：**0.2.6 = 文本集中化这一版**（当前），**0.3 = 玩家润色文本之后重新编译的那一版**。

文本改动只影响常量与资源，不改变任何渲染逻辑，所以不需要额外的实机验证；
编译后我们仍会跑一遍 `VerifyTool` 与两个离线回归测试。
